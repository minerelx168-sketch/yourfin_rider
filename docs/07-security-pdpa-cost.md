# 07 — ความปลอดภัย, PDPA และต้นทุน

## 7.1 PDPA (พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562) — อ่านก่อนเปิดใช้จริง

ระบบนี้เก็บข้อมูลส่วนบุคคล 2 กลุ่มที่ต้องระวัง:

1. **พิกัด/การเคลื่อนไหวของพนักงาน (เซลล์ไรเดอร์)** — ถือเป็นข้อมูลส่วนบุคคล และการติดตามตำแหน่ง
   เป็นเรื่องอ่อนไหวด้านสิทธิแรงงาน
2. **ข้อมูลร้านค้า/เจ้าของร้าน** (ชื่อ, เบอร์, ที่ตั้ง, รูปหน้าร้าน)

**สิ่งที่ควรทำให้ถูกต้องตามกฎหมาย:**
- [ ] จัดทำ **หนังสือแจ้งการประมวลผลข้อมูล (Privacy Notice)** + **ขอความยินยอม** จากพนักงาน
      ระบุ *วัตถุประสงค์* (วัด KPI/ระยะทางทำงาน), *ข้อมูลที่เก็บ*, *ระยะเวลาเก็บ*, *สิทธิเจ้าของข้อมูล*
- [ ] เก็บพิกัด **เฉพาะช่วงเวลางาน** (ผูกกับ Clock-in/Clock-out) ไม่ติดตามนอกเวลางาน
- [ ] กำหนด **นโยบายเก็บรักษา/ลบข้อมูล** (เช่น เก็บ 12–24 เดือนแล้ว archive/ลบ)
- [ ] จำกัดผู้เข้าถึงข้อมูลดิบตามหน้าที่ (least privilege)
- [ ] มีฐาน *ความยินยอม/สัญญา* สำหรับเก็บข้อมูลเจ้าของร้านค้า และแจ้งวัตถุประสงค์

> ⚖️ นี่เป็นคำแนะนำเชิงสถาปัตยกรรม ไม่ใช่คำปรึกษากฎหมาย — ควรให้ฝ่ายกฎหมาย/DPO ตรวจร่างจริง

## 7.2 ความปลอดภัยของระบบ (Security Hardening)

**API Key (Google Maps):**
- เก็บใน **Script Properties เท่านั้น** — ห้าม hard-code หรือ commit ลง Git
- **Restrict key** ให้ใช้ได้เฉพาะ *Distance Matrix API*
- ตั้ง **budget alert** ใน Cloud Billing กันบิลพุ่งผิดปกติ

**Web App / Webhook:**
- ป้องกันด้วย `WEBHOOK_SECRET` (โค้ดตรวจทุกครั้งใน `doPost`)
- หมุนเปลี่ยน secret เป็นระยะ; อย่าใส่ secret ลงโค้ดหรือ commit

**Google Sheets:**
- แชร์ Sheet ให้ **เฉพาะ Admin/ระบบ** — เซลล์เข้าผ่าน *แอป AppSheet* ไม่ใช่ Sheet ตรง ๆ
- ผู้บริหารเข้าผ่าน *Looker (Viewer)* ไม่ต้องเปิด Sheet
- เปิด **Version history** ไว้ตรวจย้อนหลัง

**AppSheet:**
- ใช้ **Security filter** (role-based) ให้ Sales เห็นเฉพาะข้อมูลตัวเอง (ดู `docs/03 ▸ 3.6`)
- ตั้งคอลัมน์ของ backend เป็น `Editable=FALSE` กันแก้มือ

**บัญชี/สิทธิ์:**
- ใช้บัญชี Google Workspace ขององค์กร (ไม่ใช่ส่วนตัว) เป็นเจ้าของระบบ
- ทำ **service/owner account** กลางเพื่อไม่ผูกกับพนักงานคนใดคนหนึ่ง (กันคนลาออกแล้วระบบล่ม)

## 7.3 ประมาณการต้นทุน (Cost Model)

> ราคาจริงเปลี่ยนได้ — ตรวจ **Google Maps Platform Pricing** และ **AppSheet Pricing** ล่าสุดก่อนสรุปงบ

### Google Maps Distance Matrix
- คิดเป็น **element** = (origins × destinations). การคำนวณ **ทีละ leg = 1 element/leg**
- ตัวอย่างทีม **10 คน × 15 เช็คอิน/วัน × 22 วันทำงาน**:

| รายการ | ค่า |
|---|---|
| legs ต่อเดือน | 10 × 15 × 22 = **3,300 elements** |
| อัตราอ้างอิง (Standard ~$5 / 1,000 elements) | 3,300 / 1,000 × $5 = **~$16.5/เดือน** |
| ลดเพิ่มด้วย **cache** (leg ซ้ำ เช่นเส้นทางประจำ) | ต่ำกว่านี้ |
| Free tier รายเดือนของ Google Maps | หักลบได้อีก |

→ ระดับ **หลักร้อยบาท/เดือน** สำหรับทีมขนาดนี้

### AppSheet
- คิด **ต่อผู้ใช้/เดือน** (แพ็กเกจ Starter/Core) — เฉพาะ "เซลล์ที่บันทึกข้อมูล" + ผู้ดูแล
- ผู้บริหารที่ดูแค่ Looker **ไม่ต้องมีไลเซนส์ AppSheet**

### Looker Studio
- **ฟรี** สำหรับการใช้งานทั่วไป (Looker Studio Pro มีค่าใช้จ่ายเพิ่มถ้าต้องการฟีเจอร์องค์กร)

### Apps Script / Sheets
- **ฟรี** ภายใต้โควต้า Google Workspace (execution time, UrlFetch calls/วัน)

**สรุปงบโดยรวม:** ตัวแปรหลักคือ *จำนวนผู้ใช้ AppSheet* ส่วนค่า API แผนที่ค่อนข้างน้อยและคุมได้ด้วย cache + budget alert

## 7.4 ความเสี่ยง & การกันพลาด (Risk Register ย่อ)

| ความเสี่ยง | ผลกระทบ | การรับมือ |
|---|---|---|
| webhook ไม่ยิง/พลาด | ระยะทางไม่ถูกคำนวณ | time trigger ทุก 1 นาทีเก็บตก |
| เซลล์ปลอมพิกัด | KPI เพี้ยน | บังคับถ่ายรูปหน้าร้าน + ตรวจรัศมีกับ `Stores` |
| API key รั่ว | บิลพุ่ง | restrict key + budget alert + เก็บใน Properties |
| Sheet โตเกิน/ช้า | ระบบหน่วง | `buildDailySummary()` + archive รายเดือน → BigQuery |
| คนทำระบบลาออก | ดูแลต่อไม่ได้ | ใช้ owner account กลาง + เอกสารชุดนี้ใน Git |
| สัญญาณภาคสนามหลุด | บันทึกไม่ได้ | เปิด AppSheet offline mode |
